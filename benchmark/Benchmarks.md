# Benchmarks

## Methodology

Each benchmark fires the same event 1,000 times per frame, with the same payload every frame, for 10 seconds. The harness records the server frame rate and the bandwidth received by the client, and reports the median and the P0/P80/P90/P95/P100 percentiles for each tool.

Tools compared:

| Tool | Source |
| --- | --- |
| `roblox` | Plain `RemoteEvent` with Roblox's own serialization |
| `cheeto` | Compiled from this repository by `build.bat` |
| `zap` | Latest [Zap](https://github.com/red-blox/zap) release |
| `bytenet` | Latest [ByteNet](https://github.com/ffrostflame/ByteNet) release |

- Harness: [`src`](./src)
- Payloads: [`src/shared/benches`](./src/shared/benches)
- Definitions: [`definitions`](./definitions)

## Running the benchmarks

The harness runs inside Roblox Studio, so it needs Windows or macOS with Studio installed, plus the tools from `rokit.toml` (Rojo, darklua, Lune and run-in-roblox) and [7-Zip](https://www.7-zip.org/) for unpacking the other tools.

1. Optionally copy `config.json.example` to `config.json` and add a GitHub token to avoid API rate limits.
2. Run `build.bat`. It downloads Zap and ByteNet, compiles `Definition.cheeto` with the local compiler and builds `Benchmark.rbxl`.
3. Answer `Y` when asked to open the place. `lune run generate` then runs the place, collects the results and rewrites the tables below.

Numbers depend heavily on hardware, so compare tools against each other within one run rather than across machines.
