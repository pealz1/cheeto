# Options
Options go at the top of a source file, and allow you to configure the output of Cheeto.
```cheeto copy
option [OPTION] = [VALUE]
```

## `Casing`
Default: `Pascal`  
Options: `Pascal`, `Camel`, `Snake`  

Controls the casing with which event/function methods generate.
```cheeto copy
option Casing = Camel
```

## `ServerOutput`, `ClientOutput`, `TypesOutput`
These options allow you to specify where Cheeto will generate the respective output files.
```cheeto copy
option TypesOutput = "../Network/Types.luau"
option ServerOutput = "../Network/Server.luau"
option ClientOutput = "../Network/Client.luau"
```

## `Typescript`
Default: `false`  

Tells Cheeto whether to generate TypeScript definition files alongside Luau files.  
The generated `d.ts` files are placed in the same path as your output files.
```cheeto copy
option Typescript = true
```

## `UsePolling`
Default: `false`

Instructs the compiler to automatically output all events with a polling API.
```cheeto copy
option UsePolling = true
```

## `FutureLibrary` and `PromiseLibrary`
In order to use future and promise yield types with functions a path to each library used must be specified  
```cheeto copy
option FutureLibrary = "ReplicatedStorage.Packages.Future"
option PromiseLibrary = "ReplicatedStorage.Packages.Promise"
```

## `SyncValidation`
Default: `true`

Controls if Cheeto will check whether a sync call yielded.

## `WriteValidations`
Default: `false`

Controls if Cheeto will check types when writing them (firing an event/invoking a function). Helpful for debugging and during development, but it might result in degraded performance. It is encouraged you disable this option in production.
<Callout>
    Cheeto validates builtin primitives and container shape for arrays, maps, sets, and structs. Deep element validation follows the schema as values are serialized.
</Callout>

## `ManualReplication`
Default: `false`

Controls if Cheeto will replicate events and functions automatically at the end of every frame.  
When set to `true` automatic replication will be disabled and a `StepReplication` function will be exposed instead.

## `RemoteScope`
Default: `""`

Adds a prefix to the events generated by this Cheeto instance. For example a value of `"PACKAGE"` creates events `"PACKAGE_CHEETO_RELIABLE_REMOTE"` and `"PACKAGE_CHEETO_UNRELIABLE_REMOTE"`.
If the option is not specified, they will just be `"CHEETO_RELIABLE_REMOTE"` and `"CHEETO_UNRELIABLE_REMOTE"`.<br/>
This is particularly useful if you're using Cheeto inside of a package, and don't want to interfere with a game's own Cheeto setup.

## Runtime Guard Options
These options configure generated packet guardrails.
```cheeto copy
option MaxPacketBytes = 1048576
option MaxReliablePacketBytes = 1048576
option MaxUnreliablePacketBytes = 1000
option RateLimitPerSecond = 0
option RateLimitBurst = 0
option MaxQueuedEvents = 256
option MaxQueuedBytes = 1048576
option MaxBurstBytes = 262144
option ReliableFragmentBytes = 32768
option MaxInFlightFragments = 128
option FragmentTimeoutSeconds = 10
option LowPriorityShedding = true
option ReplayWindowSize = 128
option ReplayStaleSeconds = 30
option MaxDecodeOperations = 4096
option MaxPayloadDepth = 32
option MaxPayloadStringBytes = 65536
option MaxTableKeys = 4096
option MaxPendingInvokes = 256
option InvokeTimeoutSeconds = 0
option SecurityProfile = Development
```

`SecurityProfile` can be `Development`, `Production`, or `Competitive`. The profile supplies defaults for packet limits, rate limits, queue limits, pending invoke limits, and invoke timeouts. Explicit options override profile defaults.

`MaxPacketBytes` is the fallback packet size limit. `MaxReliablePacketBytes` and `MaxUnreliablePacketBytes` override it per transport. `ReliableFragmentBytes` controls reliable packet fragmentation; `MaxInFlightFragments` and `FragmentTimeoutSeconds` bound reassembly state per player. `MaxQueuedBytes`, `MaxQueuedEvents`, `MaxBurstBytes`, and `LowPriorityShedding` control backpressure and adaptive flush behavior. `ReplayWindowSize` and `ReplayStaleSeconds` reject stale or duplicate client packets — but **only on events that carry a sequence number**, which means events using prediction. A sequence only reaches the wire when the sender attached a prediction id, so on an ordinary event there is nothing identifying one logical call and both options are inert whatever you set them to. Use `CooldownSeconds` to bound a one-shot action that carries no sequence; the runtime enforces that by itself, and rejects before deserialising. `MaxDecodeOperations`, `MaxPayloadDepth`, `MaxPayloadStringBytes`, and `MaxTableKeys` bound decode work before user handlers run. Rate limiting is disabled when `RateLimitPerSecond` is `0`. `InvokeTimeoutSeconds` is disabled when set to `0`.

Events and functions can override the packet, queue, and rate settings:
```cheeto copy
event Attack {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    Policy: "damage",
    Risk: Damage,
    Priority: Critical,
    RateLimitPerSecond: 20,
    RateLimitBurst: 40,
    MaxQueuedEvents: 64,
    Data: u16
}
```

Generated client and server modules expose:
- `Stats()` for copied counters.
- `Configure(options)` for runtime guard changes.
- `Use(hookName, callback)` for middleware hooks.
- `CancelInvocations(reason?)` for cancelling pending client invokes.
- `SetGroup`, `AddToGroup`, `RemoveFromGroup`, and `GetGroupPlayers` for named audiences.
- `Prediction.Begin`, `Prediction.Ack`, and `Prediction.Rollback`.
- `State.DefineChannel` for local dirty-state channels.
- `Capture.Start`, `Capture.Entries`, `Capture.Replay`, `Capture.ReplayRaw`, and `Capture.Redact`.
- `Transport`, `Security`, `Diagnostics`, `Handles`, `Replication`, `State`, and `Codecs` runtime APIs for hardened v2 operation.

Server-origin events also expose `FireGroup(groupName, ...)`. Client-origin events expose `Predict(...)`, which sends the event and returns a local prediction id.

This fork only emits and accepts protocol v2. `ProtocolVersion` must be `2`; `ProtocolMode`, `AcceptProtocolVersion1`, and protocol v1 schemas fail compilation. V2 framing includes length-prefixed event frames, per-event recovery inside a packed reliable packet, prediction sequence ids and acks, reliable fragmentation and reassembly, optional integer varints, bit-packed booleans/optional presence, optional string dictionaries, and buffer pooling. Set individual `Use...` flags to disable a v2 wire optimization only when you deliberately want the simpler v2 encoding.

`CaptureRedactions` is a comma-separated default list of payload field names to hide in capture summaries. `NoRawCaptureInProduction` removes raw packet buffers from production captures so exports can be shared for diagnostics without enabling raw replay.

Client-origin events and functions should declare `Policy`, `PolicyGroup`, or `Auth`. Production hardening with `RequirePolicies = true` fails risky client-origin remotes without a policy surface. `SecurityPreset = Maximum` also enables the client shield, strict client kicks, randomized remote names, decoy remotes, and the stricter Competitive transport defaults unless you override them. Built-in policy presets cover damage, currency, trade, inventory, teleport, admin, crafting, marketplace, and moderation; games can replace or extend them at runtime with `Network.Security.RegisterPolicy`.

State channels can also be declared in schema:
```cheeto copy
channel PlayerState {
    Scope: Player,
    TickRate: 20,
    Delta: true,
    Data: struct {
        Health: u8,
        Stamina: u8,
        Equipped: string(0..32)?
    }
}
```

Generated server modules expose `Set`, `SetPlayer`, `SetAll`, `SetList`, `SetGroup`, and struct-backed `Patch` variants. Generated client modules expose `On`, `Get`, and `Version`.
