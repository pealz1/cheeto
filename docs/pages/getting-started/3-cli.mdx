# Command-Line Usage
## Compiling Descriptions
Once you have written your description file (ex. `file-name.cheeto`), you can compile it like this:

```sh copy
cheeto file-name
```

This will look for a file `file-name` with an extension `.cheeto` or `.txt`, in the current directory.

Use `--yes` for noninteractive generation in CI or scripts:

```sh copy
cheeto file-name --yes
```

### Doctor
`--doctor` validates the schema and configuration without writing output files.
It reports dangerous limits, missing output paths, disabled guardrails, and client-origin events/functions without auth, policy, or policy-group rules.

```sh copy
cheeto file-name --doctor
```

### Benchmark
`--benchmark` runs the compiler benchmark path for strict v2 output.
It reports generation time, generated byte counts for server, client, and shared type output, and the benchmark thresholds used by CI.

```sh copy
cheeto file-name --benchmark
```

### CI Reports
The rollout report modes are noninteractive when combined with `--yes`.

```sh copy
cheeto file-name --doctor --yes
cheeto file-name --benchmark --yes
cheeto file-name --load-sim --yes
cheeto file-name --capture-replay --yes
cheeto file-name --golden-snapshots --yes
cheeto file-name --compatibility --yes
cheeto file-name --schema-docs --yes
cheeto file-name --write-lock --yes
cheeto file-name --check-lock --yes
cheeto file-name --hardening-checklist --yes
```

Use `--ci --yes` to run doctor, benchmark, load-sim, capture-replay, golden-snapshots, compatibility, schema-docs, and lockfile verification in one command.

```sh copy
cheeto file-name --ci --yes
```

### Lockfile and Hardening
`--write-lock` writes the generated `cheeto.lock` beside the source schema. The lock contains protocol, schema version, schema hash, type hashes, explicit wire IDs, reserved/deprecated IDs, options, and compatibility metadata.

`--check-lock` compares the current schema with the checked-in lockfile and fails accidental wire changes.

`--hardening-checklist` is the release gate for production. It fails unsafe release configurations, including legacy protocol options, missing policies on client-origin remotes, raw production capture, disabled rate limits, unbounded packet sizes, unsafe output paths, and debug validation options.

### Watching Description Files
When you're making many rapid changes to a description file or it's imports it can be tedious to constantly have to re-run the build command.<br />
Cheeto offers a solution in the form of a `--watch` option, when passed the target file and all it's imports (including imports of imports and so on) will be watched for changes,
recompiling automatically when one occurs.
```sh copy
cheeto file-name --watch
```
