# cheeto.lock format

`cheeto --write-lock` writes `cheeto.lock` next to the schema. It does two jobs:

- **It keeps endpoint ids stable.** Every command-line compile reads it, and each endpoint keeps the id the lock recorded for its name, kind and channel. Reordering endpoints or removing one no longer renumbers the rest.
- **It puts wire changes in review.** `cheeto --check-lock` fails when the schema no longer produces the same lock, listing the lines that changed.

Commit the file next to the schema.

<Callout type="info">
Only the command-line compiler reads the lock. The Studio plugin compiles without it and numbers endpoints in declaration order, so build releases with the CLI, or pin the ids that matter with [`WireId`](/reference/fields#wireid).
</Callout>

```json
{
	"schemaVersion": 7,
	"minimumSchemaVersion": 7,
	"schemaHash": "9c41d27a0b5e83f1",
	"options": {
		"securityProfile": "Production",
		"requirePolicies": true,
		"maxReliablePacketBytes": 65536,
		"maxUnreliablePacketBytes": 900
	},
	"endpoints": {
		"DealDamage": { "kind": "Event", "channel": "Reliable", "id": 0, "shape": "5d0c8e17a4b2f963" },
		"GetInventory": { "kind": "Function", "channel": "Reliable", "id": 1, "deprecatedId": 4, "shape": "e2a90b4c7d1f5836" },
		"OldTrade": { "kind": "Event", "channel": "Reliable", "id": 2, "retired": true }
	},
	"types": {
		"Hit": "0b7e2d91c4a8f356"
	}
}
```

| Field | Contents |
| --- | --- |
| `schemaVersion`, `minimumSchemaVersion` | From the options |
| `schemaHash` | The [schema fingerprint](/reference/options/versioning#the-schema-fingerprint) the handshake compares |
| `options` | Security profile, `RequirePolicies`, and the two packet caps as written in the schema (defaults shown when unset) |
| `endpoints` | Every event, function and channel by scope-qualified name, with its kind, channel, id, `deprecatedId` and `reservedId` when set, and a hash of its payload shape |
| `types` | A hash of every declared type's shape |

## How ids are assigned

Reliable and unreliable endpoints are numbered separately, from 0 to 251. For each endpoint, in this order:

1. an explicit [`WireId`](/reference/fields#wireid);
2. the id the lock records for the same name, kind and channel;
3. the lowest free id, in declaration order.

`ReservedId` and `DeprecatedId` values, and the ids of retired endpoints, are never handed out. Two endpoints claiming one id is a compile error that names both.

## Retired endpoints

When an endpoint leaves the schema, `--write-lock` keeps its entry with `"retired": true`. Its id stays taken, so a new endpoint can never reuse it and be misread by a build that still has the old one. Delete a retired entry by hand only when no build using it can still be running.

## What --check-lock catches

`--check-lock` fails when:

- an endpoint is added, removed, renamed or renumbered;
- an endpoint's payload changes shape: a field's type, range, order, name or optionality, a channel's delta mode, or an event's delivery mode;
- a type is added, removed or changes shape;
- the version, fingerprint, profile, `RequirePolicies` or packet caps change.

The error lists the lines the schema now produces. Run `--write-lock` only when the change is intentional.

<Callout type="info">
The file may be checked out with CRLF line endings on Windows; `--check-lock` ignores the difference. A lock written by Cheeto 1.0, which had no `endpoints` section, is ignored until it is rewritten.
</Callout>
