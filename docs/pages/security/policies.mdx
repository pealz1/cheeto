# Policies

A policy decides whether a sender may use an endpoint. Endpoints name one with [`Policy`](/reference/fields#policy); you register the rule on the server with [`Security.RegisterPolicy`](/reference/api/security#registerpolicy).

```cheeto copy
function TradeAccept {
    Yield: Coroutine,
    Policy: "trade",
    PolicyGroup: "economy",
    CooldownSeconds: 0.5,
    InvokeTimeoutSeconds: 10,
    Data: u32,
    Return: boolean
}
```

```lua copy
Network.Security.RegisterPolicy("trade", function(context)
    local player = context.Source
    if not Profiles.IsLoaded(player) then
        return false, "profile-not-loaded"
    end
    if Trading.IsLocked(player) then
        return false, "trade-locked"
    end
    return true
end)
```

## How a policy runs

- It runs before the payload is decoded, after auth, cooldown and replay checks. See [The receive pipeline](/concepts/receive-pipeline).
- It receives a context: `Source`, `Name`, `Channel`, `Policy`, `PolicyGroup`, `Constraints`, `UserId` and `Size`. It does **not** receive the payload.
- Return `true` to allow. Return `false`, optionally with a reason string, to deny. The reason becomes the drop reason in violation reports, which makes logs far easier to read than a generic `PolicyRejected`.
- A policy that errors, or a name that is not registered, denies.

## The built-in names

<Callout type="error">
`damage`, `currency`, `trade`, `inventory`, `teleport`, `admin`, `crafting`, `marketplace` and `moderation` are registered at startup as **placeholders that allow any connected player**. They exist so a new schema runs out of the box. They check nothing. Register a real rule for every one your schema uses, in the same change that adds the endpoint.
</Callout>

## Policy groups

A group is a named list of policies that all must pass, in addition to the endpoint's own `Policy`. It lets several endpoints share checks, and lets you [kill](/security/kill-switches) them together.

```lua copy
Network.Security.RegisterPolicyGroup("economy", { "profile-loaded", "not-trade-locked" })
```

A group that is never registered adds no checks. A policy listed in a registered group that is not itself registered denies.

## Requiring policies

[`RequirePolicies = true`](/reference/options/security#requirepolicies) drops any client-sent endpoint that has no `Policy`. Turn it on so a forgotten policy fails closed instead of open.

<Callout type="warning">
Under `RequirePolicies`, an endpoint with only `Auth` or only `PolicyGroup` is also dropped. Give every client-sent endpoint a `Policy`. See [Limitations](/limitations#requirepolicies).
</Callout>

## Checking the payload

A policy cannot see the data. To check the data, use the [`Validate`](/security/constraints) hook or check it in your listener. A common split: the policy answers "can this player trade right now?", and the listener answers "does this player own the item in this trade?".
