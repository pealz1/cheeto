# Constraints and Validate

Constraint fields write an endpoint's rules down in the schema, next to its data: how far away a target may be, whether the sender must own it, which team they must be on. The runtime enforces them on the server before your handler runs, and drops a failing packet with `ConstraintRejected`. For functions and predicted events, the client is told the reason.

| Field | Checked | Rule |
| --- | --- | --- |
| [`RequireTeam`](/reference/fields#requireteam) | before decoding | The sender's Roblox team, or [`Replication.SetTeam`](/reference/api/replication#setteam) membership |
| [`RequireZone`](/reference/fields#requirezone) | before decoding | The zone set with [`Security.SetZone`](/reference/api/security#setzone) |
| [`RequireMatch`](/reference/fields#requirematch) | before decoding | Membership set with [`Replication.SetMatch`](/reference/api/replication#setmatch) |
| [`RequireCharacterState`](/reference/fields#requirecharacterstate) | before decoding | `Alive`, `Dead`, or a Humanoid state name |
| [`MaxDistance`](/reference/fields#maxdistance) | after decoding | Positions and parts in the payload are within range of the sender's character |
| [`RequireOwnership`](/reference/fields#requireownership) | after decoding | Instances in the payload belong to the sender |
| [`RequireObjectHandle`](/reference/fields#requireobjecthandle) | after decoding | The first number is a handle the sender may use |
| [`RequireServerKnownId`](/reference/fields#requireserverknownid) | after decoding | The first number or string is an id the server issued |
| [`RequireInventoryOwnership`](/reference/fields#requireinventoryownership) | after decoding | Your inventory resolver returns `true` |
| [`Risk`](/reference/fields#risk) | never | A tag passed to your code |

Sender constraints run before decoding, so a player who fails them costs the server no decode work. Payload constraints need the decoded values and run right after decoding, before the [`Validate`](/reference/api/hooks#validate) hook and the listener.

```cheeto copy
event Interact {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    Policy: "interact",
    RequireCharacterState: "Alive",
    MaxDistance: 12,
    RequireOwnership: true,
    Data: Instance(Model)
}
```

With that schema, a player who is dead, too far from the model, or does not own it never reaches the handler:

```lua copy
Network.Interact.On(function(player, model)
    Interactions.Run(player, model)
end)
```

## What they need from you

Some constraints check state only your game knows. Keep it current:

```lua copy
-- RequireZone
Network.Security.SetZone(player, "Arena")

-- RequireMatch
Network.Replication.SetMatch(matchId, player, true)

-- RequireOwnership: either register the owner or tag the instance
Network.Replication.SetObjectOwner(house, player, true)
house:SetAttribute("OwnerUserId", player.UserId)

-- RequireServerKnownId
Network.Security.RegisterKnownId(offerId, player)

-- RequireInventoryOwnership
Network.Security.SetInventoryResolver(function(player, payload)
    return Inventory.Has(player, payload[1])
end)
```

`RequireInventoryOwnership` with no resolver set rejects everything and warns once, so a missing resolver fails closed.

## The Validate hook

For conditions the fields cannot express, add a `Validate` hook. It runs after the built-in payload constraints and before the listener, for endpoints that declare a payload constraint. It receives `Name`, `Source`, `Channel`, `Size`, `Constraints` and `Payload` (the arguments, packed with `n`). Returning `false` drops the event with `ConstraintRejected`.

```lua copy
Network.Use("Validate", function(context)
    if context.Name ~= "Interact" then
        return true
    end

    local model = context.Payload[1]
    return not model:GetAttribute("Locked")
end)
```

One hook serves every endpoint: branch on `Name`, or write generic rules against `Constraints`.

## Where the checks stop

The payload constraints look at the arguments and the fields of table arguments, one level deep. `RequireObjectHandle` and `RequireServerKnownId` check the first number (or string) only. Values nested deeper, and rules like "the target is not the sender", belong in `Validate` or the listener. See [Limitations](/limitations#what-the-payload-constraints-examine).

<Callout type="info">
The `Validate` hook allocates a context table per event, so it is only generated for endpoints that declare a payload constraint. Endpoints without one pay nothing.
</Callout>
