# Schema versioning

The server and its clients must run modules compiled from the same schema. Normally they do: when you publish, new servers start with the new modules, and clients joining them download the new client module. Problems start when that assumption breaks, for example with long-lived servers during a rollout, or with data you stored using an old layout.

## What changes the wire

Anything that changes the bytes of a message:

- changing an endpoint's id: removing or reordering endpoints without a lockfile, or editing a [`WireId`](/reference/fields#wireid);
- changing a field's type, order, range or optionality, or an endpoint's channel or delivery mode;
- changing [encoding options](/reference/options/encoding).

Changes that do not affect the wire: whitespace, comments, renaming a type alias, reordering endpoints while `cheeto.lock` is present, and options that only affect limits or security.

## The fingerprint and the handshake

Every build carries a [fingerprint](/reference/options/versioning#the-schema-fingerprint) of its wire layout. With the [handshake](/reference/options/versioning#enableprotocolhandshake) on, both sides exchange it, and the server stops decoding a player whose fingerprint differs from its own, because those packets would be read against the wrong layout. Set [`IncompatiblePeerAction = Kick`](/reference/options/versioning#incompatiblepeeraction) to kick them with a message asking them to rejoin.

```cheeto copy
option IncompatiblePeerAction = Kick
```

`Protocol.Info(player).Peer` shows what a player reported, for logging:

```lua copy
local peer = Network.Protocol.Info(player).Peer
if peer and not peer.Compatible then
    warn(player.Name, "runs schema", peer.SchemaHash, "; the server runs", Network.Schema.Hash)
end
```

## Version numbers

[`Version`](/reference/options/versioning#version) is a number you choose, sent in the handshake and stamped on captures and saved state. You do not need to raise it for the handshake to notice a wire change, but it gives you a readable number in logs and lets [`MinimumSchemaVersion`](/reference/options/versioning#minimumschemaversion) turn away old builds explicitly.

```cheeto copy
option Version = 7
option MinimumSchemaVersion = 7
```

## Keeping ids stable

Commit [`cheeto.lock`](/reference/lockfile). The compiler reads it and gives every endpoint the id it had before, so reordering endpoints or removing one does not renumber the rest; a removed endpoint stays in the lock as retired and its id is never reused. For ids that must never move, pin them with [`WireId`](/reference/fields#wireid).

To rename or renumber an endpoint without breaking builds that still use the old id, give it a [`DeprecatedId`](/reference/fields#deprecatedid): the endpoint is sent under its new id but still accepted on the old one.

```cheeto copy
event Purchase {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    WireId: 12,
    DeprecatedId: 4,
    Data: u32
}
```

## Reviewing changes

Run `cheeto --check-lock` in CI. It fails, listing the lines that changed, whenever an endpoint is added, removed or renumbered, or a payload type changes shape, until someone regenerates the lockfile with `--write-lock`. That puts every wire change in front of a reviewer.

## Stored data

Data you saved with an [exported type](/reference/api/exports) keeps its old layout forever. Store the version next to it, and upgrade on load with [`Schema.Migrate`](/reference/api/schema#migrate):

```lua copy
Network.Schema.RegisterMigration(6, function(save)
    save.Coins = save.Gold
    save.Gold = nil
    return save
end)

local save, version = Network.Schema.Migrate(loaded.Data, loaded.Version)
```
