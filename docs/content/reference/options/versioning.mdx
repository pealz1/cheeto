# Versioning

| Option | Type | Default |
| --- | --- | --- |
| [`Version`](#version) | number | `1` |
| [`SchemaVersion`](#schemaversion) | number | `1` |
| [`MinimumSchemaVersion`](#minimumschemaversion) | number | `1` |
| [`EnableProtocolHandshake`](#enableprotocolhandshake) | boolean | `true` |
| [`IncompatiblePeerAction`](#incompatiblepeeraction) | `Drop` \| `Kick` | `Drop`, or `Kick` with `SecurityPreset = Maximum` |

For how these fit together, see [Schema versioning](/concepts/schema-versioning).

## The schema fingerprint

Every build carries a fingerprint of its wire layout, a 16-digit hex string in [`Schema.Hash`](/reference/api/schema#hash) and `cheeto.lock`. It is computed from each endpoint's name, kind, channel, wire id, deprecated id, payload type (including ranges, components and field names) and delivery mode, plus the encoding options. Two builds with the same fingerprint encode every endpoint identically. Whitespace, comments, declaration order that does not change ids, and options that do not touch the wire leave it unchanged.

## `Version`

<Spec type="number (0–65535)" default={<code>1</code>} />

A version number you choose for this schema. It is sent in the handshake, stamped on captures and state, and written to `cheeto.lock`, and compared against the peer's [`MinimumSchemaVersion`](#minimumschemaversion). It is separate from the fingerprint: you do not need to raise it for the handshake to notice a wire change, but raising it gives you a readable number in logs.

```cheeto copy
option Version = 7
```

## `SchemaVersion`

<Spec type="number (0–65535)" default={<code>1</code>} />

Alias of [`Version`](#version). When both are set, `SchemaVersion` wins.

## `MinimumSchemaVersion`

<Spec type="number (0–65535)" default={<code>1</code>} />

The oldest schema version this build accepts in a peer's handshake. A peer with a lower version is incompatible even when its fingerprint matches.

```cheeto copy
option Version = 7
option MinimumSchemaVersion = 7
```

## `EnableProtocolHandshake`

<Spec type="boolean" default={<code>true</code>} />

Each side writes a small frame with its schema version, minimum version and fingerprint: the client into its first batch, the server into the first batch of every player. The receiver records the peer in [`Protocol.Peers`](/reference/api/protocol#peers) and [`Protocol.Info`](/reference/api/protocol#info) and compares the fingerprint with its own.

When they differ on the server, the frame is dropped with `IncompatibleProtocol`, and every later packet from that player is dropped before decoding, because it would be read against the wrong layout. What else happens is set by [`IncompatiblePeerAction`](#incompatiblepeeraction). A client that receives a different fingerprint from the server warns in its output; the server decides who stays.

## `IncompatiblePeerAction`

<Spec type="identifier" default={<><code>Drop</code>, or <code>Kick</code> with <code>SecurityPreset = Maximum</code></>} values={<><code>Drop</code>, <code>Kick</code></>} />

What the server does with a player whose handshake names another schema:

| Value | Effect |
| --- | --- |
| `Drop` | The player stays in the game; its packets are dropped and reported with `IncompatibleProtocol`. |
| `Kick` | As `Drop`, and the player is kicked with a message asking them to rejoin. |

In Roblox, clients and servers of one place version normally run the same module, so a mismatch usually means a modified client or a stale server during an update.

```cheeto copy
option IncompatiblePeerAction = Kick
```
