# Endpoint fields

Fields go inside an [`event`](/reference/declarations/event), [`function`](/reference/declarations/function) or [`channel`](/reference/declarations/channel) block as `Name: Value`, separated by commas. Field names are also accepted in all lowercase, so `from: Client` works too. An unknown field, a repeated field, or a value outside a field's allowed set is a compile error.

<Callout type="info">
**Access fields belong on what clients send.** `Auth`, `Policy`, `PolicyGroup`, `CooldownSeconds`, `Idempotency` and the constraint fields are checked where a packet arrives, and rules are registered on the server. On a server-sent event or a channel they are a compile error (`Field "Policy" cannot be used here`). Rate limits and size caps are allowed everywhere: they bound work on whichever side receives.
</Callout>

## Delivery

### `From`

<Spec type="identifier" default="required" values={<><code>Server</code>, <code>Client</code></>} on="event" />

Which side sends the event. The sending side's module gets the fire methods and the receiving side gets `On` (or `Iter` for polling). Functions have no `From`: clients always invoke and the server always answers.

### `Type`

<Spec type="identifier" default={<>required for events; <code>Reliable</code> for channels</>} values={<><code>Reliable</code>, <code>Unreliable</code></>} on="event, channel" />

- `Reliable` events are batched per peer, sent once per frame over a `RemoteEvent`, arrive in order, and can be [fragmented](/concepts/batching-and-flushing#fragmentation) when large.
- `Unreliable` events are sent immediately, one `UnreliableRemoteEvent` call per `Fire`, may be lost or reordered, and are capped by [`MaxUnreliablePacketBytes`](/reference/options/limits#maxunreliablepacketbytes).

Functions are always reliable.

### `Call`

<Spec type="identifier" default="required" values={<><code>SingleSync</code>, <code>SingleAsync</code>, <code>ManySync</code>, <code>ManyAsync</code>, <code>Polling</code></>} on="event" />

How the receiving side delivers events.

| Value | Listeners | Listener runs |
| --- | --- | --- |
| `SingleSync` | One; connecting another replaces it | Inline, on the receive thread |
| `SingleAsync` | One; connecting another replaces it | In a new thread (`task.spawn`) |
| `ManySync` | Any number | Inline, in connection order |
| `ManyAsync` | Any number | Each in a new thread |
| `Polling` | None | Queued; read with `Iter` |

Sync listeners must not yield or error. A yielding sync listener delays every event after it in the same packet; [`SyncValidation`](/reference/options/runtime#syncvalidation) warns when it happens.

### `Poll`

<Spec type="boolean" default={<code>false</code>} on="event" />

`Poll: true` forces `Call` to `Polling` regardless of what `Call` says. `Call` must still be present.

### `Yield`

<Spec type="identifier" default="required" values={<><code>Coroutine</code>, <code>Future</code>, <code>Promise</code></>} on="function" />

What `Invoke` returns on the client.

| Value | `Invoke` returns | Needs |
| --- | --- | --- |
| `Coroutine` | The return value, after yielding | nothing |
| `Future` | A Future created with `Future.Try` | [`FutureLibrary`](/reference/options/output#futurelibrary) |
| `Promise` | A Promise | [`PromiseLibrary`](/reference/options/output#promiselibrary) |

### `Data`

<Spec type="type or type pack" default="no data" on="event, function, channel (required)" />

What the endpoint carries. Any [type](/reference/types/numbers), a reference to a declared type, an inline `struct`, or a parenthesized **type pack** of several values:

```cheeto copy
event Hit {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    Policy: "combat",
    Data: (Instance(Player), u16(0..500), boolean)
}
```

A type pack becomes separate arguments: `Fire(target, damage, critical)`.

### `Return`

<Spec type="type or type pack" default="no value" on="function" />

What the server's listener returns to the invoking client.

### `Predict`

<Spec type="boolean" default={<>generated unless <code>EnablePrediction = false</code></>} on="event (client-origin)" />

Client-origin events get a [`Predict`](/reference/api/event#predict) method by default. `Predict: true` keeps it even when [`EnablePrediction`](/reference/options/runtime#enableprediction) is `false` at compile time.

## Channels

### `Scope`

<Spec type="identifier" default={<code>Player</code>} values={<><code>Player</code>, <code>Global</code>, <code>Group</code>, <code>Zone</code>, <code>Party</code>, <code>Match</code>, <code>Team</code>, <code>Cell</code>, <code>Owner</code></>} on="channel" />

Chooses what the shorthand `Set`, `Patch` and `Flush` target:

| Value | `Set(...)` means |
| --- | --- |
| `Player` | `SetPlayer(player, value)` |
| `Global` | `SetAll(value)` |
| `Group` | `SetGroup(group, value)` |
| `Zone` | `SetZone(zone, value)` |
| `Party`, `Match`, `Team`, `Cell`, `Owner` | `SetScope(kind, key, value)`: every player in that party, match, team, cell or owner set |

All targeted variants are generated regardless. Party, match, cell and owner membership comes from [`Replication.SetParty`](/reference/api/replication#setparty) and its siblings; `Team` also includes every player whose Roblox `Team` has that name. [`Interest`](#interest) wins when both are set.

### `TickRate`

<Spec type="number (per second)" default="every flush" on="channel" />

How often the server automatically flushes pending changes, at most. `20` flushes at most every 50 ms. Without it, pending changes are flushed on every replication step.

### `Delta`

<Spec type="boolean" default={<><code>true</code> when <code>Data</code> is a struct</>} on="channel" />

With a struct payload, `Patch` sends only the changed fields plus a bitmask, instead of the whole value. `Delta: false` always sends the full value. Non-struct payloads always send the full value.

### `KeyframeRate`

<Spec type="number (per second)" default="none" on="channel" />

How often a full snapshot is forced even when only deltas are pending, so a client that missed state recovers.

### `Interest`

<Spec type="identifier" default={<code>None</code>} values={<><code>None</code>, <code>Zone</code>, <code>Distance</code>, <code>Party</code>, <code>Match</code>, <code>Team</code>, <code>Cell</code>, <code>Owner</code></>} on="channel" />

`Zone` maps `Set`/`Patch` to `SetZone`/`PatchZone`, and `Distance` maps them to `SetDistance`/`PatchDistance`. `Party`, `Match`, `Team`, `Cell` and `Owner` map them to `SetScope`/`PatchScope` with that kind, as for [`Scope`](#scope). `None` leaves `Scope` in charge. See [Audiences and routing](/concepts/interest-and-routing).

### `InterestRadius`

<Spec type="number (studs)" default={<code>0</code>} on="channel" />

Default radius for the `Distance` variants when no radius is passed.

## Access control

### `Auth`

<Spec type="string" default="none" on="client-sent event, function" />

Names an [auth rule](/security/auth-rules) that must return `true` for each received event. Register rules with [`UseAuth`](/reference/api/module#useauth). The built-in rules are `AlivePlayer` (sender is a player still in the game) and `ServerOnly` (sender is the server).

A rule name that was never registered drops **every** packet on the endpoint with `AuthRejected`, and logs one warning per name. A rule that errors also drops.

```cheeto copy
event UseItem {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    Auth: "AlivePlayer",
    Policy: "inventory",
    Data: u16
}
```

### `Policy`

<Spec type="string" default="none" on="client-sent event, function" />

Names a [policy](/security/policies) that must allow the sender. Policies run before the payload is decoded and receive a context with the sender, endpoint name, constraints and packet size. Register them with [`Security.RegisterPolicy`](/reference/api/security#registerpolicy).

Policies fail closed: a name nobody registered drops every packet on the endpoint with `PolicyRejected` and warns once. A policy can return a reason string as its second value, which becomes the drop reason and, for functions and predictions, the reason the client is told.

### `PolicyGroup`

<Spec type="string" default="none" on="event, function" />

Names a group registered with [`Security.RegisterPolicyGroup`](/reference/api/security#registerpolicygroup). Every policy in the group must allow the sender. A group that was never registered drops every packet with `PolicyRejected` and warns once, like an unregistered policy. The group name is also the unit for [`Security.KillPolicyGroup`](/reference/api/security#killpolicygroup).

### `Honeypot`

<Spec type="boolean" default={<code>false</code>} on="event, function" />

Marks an endpoint that no legitimate code calls. Traffic on it is dropped before rate limiting and decoding, with reason `Honeypot`. See [Honeypots](/security/honeypots).

## Limits

### `CooldownSeconds`

<Spec type="number (seconds)" default={<><code>0</code> (off)</>} on="event, function" />

Minimum time between two accepted calls from the same sender on this endpoint. Calls inside the window are dropped with `Cooldown` before decoding. Enforced by the runtime; no rule needed.

Set it looser than the client's own retry interval, or legitimate retries are dropped.

### `RateLimitPerSecond`

<Spec type="number" default={<>the schema's <code>RateLimitPerSecond</code> option if written, else off</>} on="event, function, channel" />

A per-sender token bucket for this endpoint. Excess events are dropped with `RateLimit`. See [`RateLimitPerSecond`](/reference/options/limits#ratelimitpersecond) for how this interacts with the per-packet limit.

### `RateLimitBurst`

<Spec type="number" default={<>the schema option, else equal to the rate</>} on="event, function, channel" />

Bucket capacity for this endpoint.

### `MaxPacketBytes`

<Spec type="number (bytes)" default={<>the schema's <code>MaxPacketBytes</code> option if written, else no per-endpoint check</>} on="event, function, channel" />

Drops this endpoint's event with `MaxPacketBytes` when its own frame is larger than this many bytes. Other events batched in the same packet do not count against it; the packet as a whole is bounded by [`MaxReliablePacketBytes`](/reference/options/limits#maxreliablepacketbytes) and [`MaxUnreliablePacketBytes`](/reference/options/limits#maxunreliablepacketbytes).

### `MaxQueuedEvents`

<Spec type="number" default={<>the schema option, else <code>256</code></>} on="event, function, channel" />

Maximum events waiting for a listener (or for `Iter`) on this endpoint before new ones are dropped with `QueueFull`.

### `MaxPendingInvokes`

<Spec type="number" default={<>the runtime's <code>MaxPendingInvokes</code></>} on="function" />

Maximum invokes of this function waiting for a reply on one client. `Invoke` raises an error beyond it, before anything is sent.

### `InvokeTimeoutSeconds`

<Spec type="number (seconds)" default={<>the runtime's <code>InvokeTimeoutSeconds</code></>} on="function" />

How long `Invoke` waits before raising `Invoke timed out after N seconds.` Without this field the runtime value applies, which is the security profile's default (10 s for Production, 5 s for Competitive, none for Development), the schema option when written, or whatever [`Configure`](/reference/api/module#configure) set last.

## Replay

### `Idempotency`

<Spec type="boolean" default={<code>false</code>} on="client-sent event, function" />

Every send carries a 16-bit sequence number, and the server drops a packet whose number is not newer than the last one it accepted from that sender, with reason `OutOfOrder`. A captured packet sent a second time is therefore never delivered twice. Predicted sends are also deduplicated by prediction id for 120 seconds, with `ReplayDuplicate`.

This stops replays. A packet built from scratch with a fresh number is a new request; see [Replay and idempotency](/security/replay-and-idempotency).

## Constraints

Constraints are enforced by the runtime, on the server, before your handler runs. The **sender** constraints (`RequireTeam`, `RequireZone`, `RequireMatch`, `RequireCharacterState`) are checked before the payload is decoded; the **payload** constraints (`MaxDistance`, `RequireOwnership`, `RequireObjectHandle`, `RequireServerKnownId`, `RequireInventoryOwnership`) after it, looking at the arguments and the fields of table arguments one level deep. A rejected packet is dropped with `ConstraintRejected`.

Every constraint is also passed to your policies and to the [`Validate`](/reference/api/hooks#validate) hook as `Constraints`, so you can add conditions of your own. `Validate` runs for endpoints that declare a payload constraint. See [Constraints and Validate](/security/constraints).

### `Risk`

<Spec type="identifier" default="none" on="event, function, channel" />

A free-form tag, such as `Damage` or `Currency`, passed as `Constraints.Risk`. It checks nothing and does not trigger `Validate`.

### `MaxDistance`

<Spec type="number (studs)" default={<><code>0</code> (off)</>} on="client-sent event, function" />

Every `Vector3`, `CFrame`, `BasePart`, `Model` and `Attachment` in the payload must be within this distance of the sender's `HumanoidRootPart` (or character pivot). When the payload contains a position and the sender has no character, the packet is rejected. Payloads without positions pass.

```cheeto copy
event PlaceBlock {
    From: Client,
    Type: Reliable,
    Call: SingleAsync,
    Policy: "building",
    MaxDistance: 24,
    Data: vector
}
```

### `RequireOwnership`

<Spec type="boolean" default={<code>false</code>} on="client-sent event, function" />

Every Instance in the payload must belong to the sender: registered to them with [`Replication.SetObjectOwner`](/reference/api/replication#setobjectowner), inside their character, or carrying an `OwnerUserId` attribute equal to their `UserId`. Ancestors count, so a part of an owned model is owned.

### `RequireTeam`

<Spec type="string" default="none" on="client-sent event, function" />

The sender's Roblox `Team` must have this name, or the sender must have been added to it with [`Replication.SetTeam`](/reference/api/replication#setteam).

### `RequireZone`

<Spec type="string" default="none" on="client-sent event, function" />

The sender must be in this zone, as set with [`Security.SetZone`](/reference/api/security#setzone).

### `RequireMatch`

<Spec type="string" default="none" on="client-sent event, function" />

The sender must be in this match, as set with [`Replication.SetMatch`](/reference/api/replication#setmatch).

### `RequireInventoryOwnership`

<Spec type="boolean" default={<code>false</code>} on="client-sent event, function" />

Calls the resolver set with [`Security.SetInventoryResolver`](/reference/api/security#setinventoryresolver) with the sender and the decoded arguments, and rejects unless it returns `true`. Until a resolver is set, every packet is rejected and one warning is logged.

### `RequireCharacterState`

<Spec type="string" default="none" on="client-sent event, function" />

`Alive` requires a character whose Humanoid has health above 0, `Dead` the opposite. Any other value is compared with the name of the Humanoid's current state, for example `Running` or `Freefall`.

### `RequireObjectHandle`

<Spec type="boolean" default={<code>false</code>} on="client-sent event, function" />

The first number in the payload must be a [handle](/security/handles-and-capabilities) that resolves for the sender with [`Handles.Resolve`](/reference/api/handles#resolve).

### `RequireServerKnownId`

<Spec type="boolean" default={<code>false</code>} on="client-sent event, function" />

The first number or string in the payload must be an id registered with [`Security.RegisterKnownId`](/reference/api/security#registerknownid), for this sender or for anyone.

## Scheduling

### `Priority`

<Spec type="identifier" default={<code>Gameplay</code>} values={<><code>Critical</code>, <code>Gameplay</code>, <code>Cosmetic</code>, <code>Background</code></>} on="event, function, channel" />

Decides which outgoing events may be shed under backpressure: `Cosmetic` and `Background` events are dropped with `Backpressure` when the peer's tracked queue is over [`MaxQueuedBytes`](/reference/options/limits#maxqueuedbytes) and [`LowPriorityShedding`](/reference/options/limits#lowpriorityshedding) is on. It does not reorder events or change when they are flushed.

### `ReliabilityMode`

<Spec type="identifier" default={<>follows <code>Type</code></>} values={<><code>Reliable</code>, <code>Unreliable</code>, <code>Sequenced</code>, <code>Latest</code></>} on="event" />

| Value | Delivery |
| --- | --- |
| `Reliable`, `Unreliable` | Same as `Type`; a value that contradicts `Type` is a compile error |
| `Sequenced` | Every send carries a 16-bit sequence number; the receiver drops anything not newer than the last one it accepted from that peer, with `OutOfOrder`. Use it on unreliable events where a stale value is worse than none, such as positions |
| `Latest` | Only the last send per recipient in each replication step is delivered; earlier ones are discarded before they are sent. A replaced prediction rolls back with the reason `Superseded` |

```cheeto copy
event AimDirection {
    From: Client,
    Type: Unreliable,
    Call: ManyAsync,
    ReliabilityMode: Latest,
    Data: vector
}
```

### `CoalesceKey`

<Spec type="string" default="none" on="event" />

`Latest` delivery with a shared slot: every event with the same key replaces the previous one queued for the same recipient in this replication step, whichever endpoint it came from. Use it when several endpoints describe one piece of state and only the newest matters.

## Identity

### `WireId`

<Spec type="number (0–251)" default={<>the lock's id, else the lowest free one</>} on="event, function, channel" />

Pins the id this endpoint is sent under on its channel. Two endpoints on one channel with the same id is a compile error. Without it, the endpoint keeps the id recorded in [`cheeto.lock`](/reference/lockfile), or takes the lowest free id in declaration order. See [Keeping ids stable](/concepts/schema-versioning#keeping-ids-stable).

### `ReservedId`

<Spec type="number (0–251)" default="none" on="event, function, channel" />

Reserves an id on this endpoint's channel so nothing else is assigned it, for example the id of an endpoint you removed before the project had a lockfile.

### `DeprecatedId`

<Spec type="number (0–251)" default="none" on="event, function, channel" />

The id this endpoint used before. It is sent under its current id but still accepted on this one, so builds from before a renumbering keep working, and the old id is reserved. Remove it once no such build can be running.
